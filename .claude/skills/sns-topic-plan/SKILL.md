# 주제 기획 (0단계)

기준 문서: `sns-automation/PRD.md` 5장. 명령은 `sns-automation/`에서 실행한다.

## 1. 현황 파악
- 오늘 날짜·요일(KST)과 이번 주(`node sns.js plan` 첫 줄)를 확인한다.
- `node sns.js topic` → 남은 후보. 같은 주제를 다시 제안하지 않는다.
- `node sns.js topic list all`, `data/contents.json` → 최근 만든 주제와 완료 현황.
- `data/income.json` → 수익이 난 출처. 수익이 난 라인·상품군에 가산점을 준다.

## 2. 근거 수집
- 이번 주와 다음 주의 계절, 날씨, 기념일, 행사(명절, 시험, 휴가, 블랙프라이데이, 연말 등)를 정리한다.
- 웹 검색이 가능하면 운동·홈트, 운동 용품, 플레이리스트 분위기의 최근 검색 흐름을 확인한다. 확인하지 못한 수치는 쓰지 않는다.

## 3. 후보 만들기
라인별 `weeklyTarget` + 1개씩 (`config/pipelines.json`). 우선순위: shopping → blog → workout → music.
- **운동 ↔ 쇼핑 연결**: 운동 주제마다 쓰는 용품을 쇼핑 후보로 하나씩 연결하고 `--links`에 적는다.
- **음악**: 상황 + 분위기 + 시간대로 구체화한다 (예: "비 오는 월요일 아침 출근길 로파이").
- **블로그**: 검색어 중심 가제 ("~하는 법", "~추천 기준").
- 점수(1~5): 수익성, 쉬움(제작 난이도의 역수), 채널 적합도.

각 후보를 저장한다:
```bash
node sns.js topic add <라인> "<가제>" --why "<이번 주 근거>" --keywords "검색어1,검색어2" --links "<연결>" --score 4,3,5
```

## 4. 보고
`plans/<주>-topics.md`에 라인별 후보 표(점수, 가제, 근거, 연결)를 저장하고, 사용자에게는 라인별 추천 1개씩만 짧게 보여준다.
승인은 사용자가 `node sns.js topic pick <id>`로 한다. 이 스킬은 후보를 본편으로 확정하지 않는다.

## 금지
- 상품 링크, 가격, 효과, 검색량을 지어내지 않는다. 모르면 "확인 필요".
- 매주 같은 일반론 금지. 근거는 그 주 날짜에만 맞아야 한다.
