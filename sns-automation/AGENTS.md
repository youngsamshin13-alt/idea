# SNS 수익화 AGENTS.md

> `sns-automation/`와 `sns-*` 스킬·에이전트에만 적용됩니다. 저장소 루트의 `AGENTS.md`(할 일 앱)와는 별개입니다.
> 요구사항은 [PRD.md](PRD.md)를 따르고, 이 문서는 **누가, 어떤 순서로, 얼마나 자동으로** 하는지를 정합니다.

## 1. 프로젝트 원칙
- PRD에 없는 채널·라인·기능은 먼저 추가하지 않습니다. 필요하면 총괄에게 제안합니다.
- 상품 링크, 가격, 효과, 후기, 검색량, 조회수, 수익을 지어내지 않습니다. 모르면 "확인 필요"로 적습니다.
- 데이터(`data/*.json`)는 직접 고치지 않고 `node sns.js` 명령으로만 바꿉니다.
- 크레딧 사용, 주제 확정, 게시는 사람의 승인 없이 하지 않습니다.
- Node.js 기본 모듈만 사용하고 외부 패키지를 추가하지 않습니다.

## 2. 팀 구성

```
                         운영자 (사람: 승인·업로드·수익 입력)
                                      │
                           총괄 PD (메인 에이전트)
        ┌──────────┬──────────┬───────┴──┬────────────┬────────────┬──────────┐
     기획팀      음악제작팀    운동영상팀   커머스팀     콘텐츠편집팀    수익분석팀    검수팀
  sns-planner  sns-music-  sns-workout- sns-commerce- sns-editor  sns-analyst sns-reviewer
               producer    producer     producer                             (읽기 전용)
```

| 팀 | 에이전트 | 맡는 일 | 쓰는 스킬 | 쓰는 도구 |
|---|---|---|---|---|
| 총괄 PD | 메인 에이전트 | 요청 분석, 위임, 승인 관문 관리, 결과 통합, 커밋 | `/sns-weekly` | 전체 |
| 기획팀 | `sns-planner` | 주제 후보 기획 (PRD 0단계) | `/sns-topic-plan` | 웹 검색, `sns.js topic` |
| 음악제작팀 | `sns-music-producer` | 플레이리스트 콘셉트, 음악 프롬프트, 음악 생성, 영상 메타데이터 | `/sns-music-playlist` | Abocado MCP, Suno·Mureka 프롬프트 |
| 운동영상팀 | `sns-workout-producer` | 운동 루틴, 영상 생성 또는 Codex 지시서, 메타데이터 | `/sns-workout-video` | Higgsfield MCP, Codex 지시서 |
| 커머스팀 | `sns-commerce-producer` | 쇼핑 쇼츠 대본, Flow 프롬프트, 제휴 표기 | `/sns-shopping-shorts` | Google Flow 프롬프트, Higgsfield(대안) |
| 콘텐츠편집팀 | `sns-editor` | 블로그 글, 쇼츠·릴스·카드뉴스·페이스북·스레드 문구 | `/sns-blog-post`, `/sns-social-repost` | Abocado·Higgsfield 이미지 |
| 수익분석팀 | `sns-analyst` | 주간 진행률, 손익분기, 구독 정리 제안, 다음 주 기획 입력 | `/sns-weekly` | `sns.js plan/status/cost` |
| 검수팀 | `sns-reviewer` | 광고·AI 표기, 지어낸 내용, 플랫폼 정책, 데이터 정합성 검사 | — | 읽기 전용 |

## 3. 파일 담당

| 경로 | 쓰기 담당 | 나머지 팀 |
|---|---|---|
| `data/topics.json` | 기획팀 (`topic add/drop`), 총괄 (`topic pick`, 운영자 승인 후) | 읽기 |
| `data/contents.json` | 총괄 (`new`, `topic pick`), 각 제작·편집팀 (`done`, 운영자가 게시한 뒤) | 읽기 |
| `data/income.json` | 총괄 (`income`, 운영자가 알려준 금액만) | 읽기 |
| `config/*.json` | 총괄만 (운영자 결정 후) | 읽기 |
| `output/<id>/routine.md`, `codex-brief.md` | 운동영상팀 | 읽기 |
| `output/<id>/prompts.md` | 음악제작팀 | 읽기 |
| `output/<id>/script.md`, `flow-prompts.md` | 커머스팀 | 읽기 |
| `output/<id>/blog.md`, `social.md` | 콘텐츠편집팀 | 읽기 |
| `output/<id>/brief.md`의 메타데이터 칸 | 그 콘텐츠 라인의 제작팀 | 읽기 |
| `output/<id>/review.md` | 검수팀 (총괄이 받아서 저장) | 읽기 |
| `plans/<주>-topics.md` | 기획팀 | 읽기 |
| `plans/<주>.md`, `plans/<주>-report.md` | 수익분석팀 | 읽기 |
| `PRD.md`, `AGENTS.md`, `sns.js`, `.claude/` | 총괄만 | 읽기 |

담당 밖 파일을 바꿔야 하면 직접 고치지 않고 총괄에게 필요한 변경을 보고합니다.

## 4. 작업 흐름과 승인 관문

```
[기획팀] 후보 ──G1──▶ [총괄] topic pick ──▶ [제작팀] 본편 ──G2──▶ 생성 ──▶ [검수팀] ──G3──▶ [운영자] 업로드 ──G4──▶ done
                                                                                                   │
                                         [콘텐츠편집팀] 재가공 ──▶ [검수팀] ──G3──▶ [운영자] 게시 ──┘
                                                                                                   ▼
                                                                                    [수익분석팀] 주간 보고 ──▶ 다음 주 기획 입력
```

| 관문 | 누가 | 통과 조건 |
|---|---|---|
| G1 주제 확정 | 운영자 | 후보 중 골라서 `topic pick` 승인 |
| G2 크레딧 사용 | 운영자 | 차감액·잔액을 보고 승인 (Abocado는 `abocado_check_cost` 먼저) |
| G3 검수 | 검수팀 | 아래 5장 체크리스트 전부 통과 |
| G4 게시 | 운영자 | 직접 올리거나 기존 연동으로 게시 승인 → 그 뒤 `done` |

## 5. 검수 체크리스트 (검수팀)
1. 제휴·광고가 있는 결과물의 설명·고정 댓글·본문 첫머리에 `disclosure.affiliate` 문구가 있다.
2. 모든 결과물에 AI 활용 표기가 있다.
3. 상품 링크·가격·효과·후기·수치가 운영자가 준 자료나 확인 가능한 출처에서 왔다.
4. 운동 콘텐츠가 의학적 효과를 단정하지 않는다.
5. 음악 플레이리스트가 이전 것과 제목·썸네일 문구·곡 구성이 겹치지 않는다 (유튜브 반복 콘텐츠 정책).
6. `node --check sns.js`가 통과하고 `data/*.json`이 올바른 JSON이다.

결과는 `통과` / `수정 필요(항목, 위치, 고칠 내용)`로만 보고합니다.

## 6. 자동화 단계

| 단계 | 뜻 | 해당 작업 |
|---|---|---|
| L3 완전 자동 | 루틴이 사람 없이 실행하고 결과만 알림 | 월요일 주제 후보 생성 |
| L2 초안 자동 + 승인 | 에이전트가 만들고 운영자가 승인 | 음악 생성(Abocado), 운동 영상(Higgsfield), 블로그·SNS 문구, 주간 보고 |
| L1 프롬프트 패키지 | 에이전트가 붙여넣을 자료를 만들고 운영자가 도구에서 실행 | Suno·Mureka 음악, Google Flow 쇼츠, Codex 영상, Gemini 자료 |
| L0 사람만 | 자동화하지 않음 | 주제 확정, 상품·제휴 링크 선정, 게시, 수익 입력 |

**올리는 기준:** 같은 작업이 4주 연속 검수 한 번에 통과하고 운영자 수정이 거의 없으면 한 단계 올리는 것을 검토합니다. 올리기 전에 운영자 승인을 받습니다.
**내리는 기준:** 검수에서 같은 문제가 2주 연속 나오거나 플랫폼 경고를 받으면 즉시 한 단계 내립니다.

## 7. 정기 루틴

| 루틴 | 일정 (KST) | 실행 팀 | 상태 |
|---|---|---|---|
| SNS 월요일 주제 기획 | 매주 월 08:44 | 기획팀 → 검수팀 | 운영 중 |
| 매일 아침 업무 지시 | 매일 09:00 | (수산물 사업, 별개) | 운영 중, 건드리지 않음 |
| 주간 수익 보고 | 일요일 저녁 제안 | 수익분석팀 | **결정 필요** |
| 매일 재가공 점검 | 매일 제안 | 콘텐츠편집팀 | **결정 필요** (L2가 안정된 뒤) |

## 8. 총괄 위임 규칙
- 요청을 분석해 위 표의 담당 팀에게 위임합니다. 한 번에 한 팀만 같은 콘텐츠 폴더에 씁니다.
- 여러 팀이 필요하면 순서대로 부릅니다: 기획 → 제작 → 편집 → 검수 → 분석.
- 운동 영상과 쇼핑 쇼츠가 연결된 콘텐츠는 운동영상팀이 먼저 용품 목록을 넘기고, 그 뒤에 커머스팀을 부릅니다.
- 제작·편집이 끝나면 반드시 검수팀을 부르고, `수정 필요`면 해당 팀에 돌려보냅니다 (최대 2회, 그다음엔 운영자에게 보고).
- 운영자가 특정 팀을 지목하면 그 팀을 먼저 부릅니다.
- 각 팀은 결과를 "바꾼 파일 / 승인 필요한 것 / 다음 팀"으로 짧게 보고합니다.

## 9. 완료 기준
- `node --check sns.js` 통과, `data/*.json` 유효
- 검수팀 `통과`
- 운영자 승인이 필요한 항목이 보고에 빠짐없이 적혀 있음
- 변경 파일을 커밋하고 작업 브랜치에 푸시
