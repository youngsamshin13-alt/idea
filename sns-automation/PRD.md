# SNS 수익화 자동화 PRD

> 이 문서는 `sns-automation/`에만 적용됩니다. 저장소 루트의 `PRD.md`(할 일 앱)와는 별개입니다.

## 1. 목적
AI 구독 도구로 만든 콘텐츠를 YouTube, 인스타그램, 페이스북, 스레드, 블로그에 나눠 올리고, 그 수익으로 **월 구독료(약 52만 원)를 넘기는 것**이 목표입니다.

## 2. 사용자
1인 운영자 한 명. 기획과 승인은 사람이 하고, 제작·재가공·정리는 Claude Code 스킬이 맡습니다.

## 3. 전체 흐름

```
0. 주제 기획 ─▶ 1. 본편 등록 ─▶ 2. 본편 제작 ─▶ 3. 재가공 배포 ─▶ 4. 수익 기록·회고
  (월요일 루틴)    topic pick       라인별 스킬       social-repost       income / cost
  /sns-topic-plan                                   blog-post
```

| 단계 | 담당 | 결과물 | 사람이 할 일 |
|---|---|---|---|
| 0. 주제 기획 | 월요일 루틴 → `/sns-topic-plan` | `data/topics.json`의 후보(proposed), `plans/<주>-topics.md` | 후보를 승인하거나 버리기 |
| 1. 본편 등록 | `node sns.js topic pick <id>` | `data/contents.json` 항목 + 채널별 작업 | — |
| 2. 본편 제작 | `/sns-music-playlist`, `/sns-workout-video`, `/sns-shopping-shorts`, `/sns-blog-post` | `output/<id>/` | 크레딧 사용 승인, 업로드 |
| 3. 재가공 배포 | `/sns-social-repost`, `/sns-blog-post` | 채널별 문구 | 게시 승인 |
| 4. 기록·회고 | `node sns.js income`, `cost`, `/sns-weekly` | 손익, 주간 계획 | 수익 금액 입력 |

## 4. 콘텐츠 라인
| 라인 | 목적 | 주간 목표 | 우선순위 |
|---|---|---|---|
| shopping 쇼핑 쇼츠 (운동 용품 중심) | 빠른 현금 (제휴 수수료) | 3 | 1 |
| blog 블로그 | 검색 유입 + 제휴 링크 | 2 | 2 |
| workout 운동 영상 | 신뢰 쌓기 (애드센스, 이후 협찬) | 2 | 3 |
| music 음악 플레이리스트 | 장기 자산 (애드센스) | 2 | 4 |

스레드는 별도 라인을 두지 않고 재가공 채널로만 씁니다.

## 5. 주제 기획 단계 (0단계)

### 5.1 언제
- 매주 **월요일 08:44 (KST)** 루틴이 자동으로 후보를 만듭니다.
- 주중에 필요하면 `/sns-topic-plan`을 직접 실행합니다.

### 5.2 입력
1. 날짜, 계절, 그 주의 기념일·행사(명절, 시험, 휴가철, 연말 등)
2. 지난주 결과: `data/contents.json`의 완료 현황, `data/income.json`의 수익 출처
3. 아직 남은 후보: `data/topics.json`의 proposed 항목 (중복 제안 방지)
4. 라인 간 연결: 운동 영상 주제에서 쓰는 용품 → 쇼핑 쇼츠 후보

### 5.3 출력
- 라인별 주간 목표 수만큼 + 여유 1개씩 후보를 만듭니다 (주 최대 13개).
- 후보마다 다음을 기록합니다.

| 항목 | 설명 |
|---|---|
| line | music / workout / shopping / blog |
| title | 가제 |
| why | 이번 주에 해야 하는 이유 (계절·행사·지난주 성과 근거) |
| keywords | 검색어 2~3개 |
| links | 연결할 다른 라인 콘텐츠 (예: 운동 → 쇼핑) |
| score | 수익성, 제작 난이도(쉬울수록 높음), 채널 적합도를 각 1~5로 매긴 값 |

- 점수는 정렬용 참고값입니다. 최종 선택은 운영자가 합니다.

### 5.4 상태
`proposed`(후보) → `used`(본편으로 등록됨) 또는 `dropped`(버림)

### 5.5 원칙
- 상품 링크, 가격, 효과, 트렌드 수치를 지어내지 않습니다. 확인이 필요한 건 "확인 필요"로 적습니다.
- 매주 같은 일반론을 반복하지 않습니다. 그 주의 날짜에만 맞는 근거를 적습니다.
- 루틴은 후보만 만들고 본편으로 확정하지 않습니다.

## 6. 데이터
| 파일 | 내용 |
|---|---|
| `config/pipelines.json` | 라인, 채널, 파생 규칙, 광고·AI 표기 문구 |
| `config/subscriptions.json` | 구독 도구, 월 비용, 겹치는 구독 |
| `data/topics.json` | 주제 후보 |
| `data/contents.json` | 본편과 채널별 작업 상태 |
| `data/income.json` | 월별 수익 |
| `output/<id>/` | 콘텐츠별 기획서, 프롬프트, 대본, 문구 |
| `plans/` | 주간 계획, 주제 후보 보고서 |

## 7. 루틴
| 이름 | 일정 (KST) | 하는 일 |
|---|---|---|
| SNS 월요일 주제 기획 | 매주 월 08:44 | 0단계 실행 → 후보 저장 → 커밋·푸시 → 요약 알림 |

기존 "매일 아침 업무 지시"(수산물 사업) 루틴과는 별개로 운영합니다.

## 8. 제약
- Node.js 기본 모듈만 사용하고 외부 패키지를 추가하지 않습니다.
- 크레딧이 드는 생성은 차감액을 먼저 보여주고 승인을 받습니다.
- 업로드·게시는 운영자 확인 후에만 합니다.
- 제휴 콘텐츠에는 광고 표기를, 모든 콘텐츠에는 AI 활용 표기를 넣습니다.
- 클라우드 루틴은 운영자 PC 파일이나 채널 통계에 접근할 수 없으므로, 실제 조회수·수익을 아는 척하지 않습니다.

## 9. 성공 기준
- 주간 본편 목표(9개)의 80% 이상 등록
- 본편 하나당 파생 작업 완료율 80% 이상
- 월 수익 ≥ 월 구독료

## 10. 하지 않는 것 (지금 단계)
- SNS 자동 게시 API 연동 (현재 쓰는 연동 방식 유지)
- 채널 통계 자동 수집
- 지원사업 자동 지원 (Codex에서 별도로 운영)
